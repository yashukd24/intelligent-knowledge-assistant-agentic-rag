## 1. Executive Summary

This report establishes local LLM inference support for the Intelligent Knowledge Assistant using **Ollama** and the existing local model **`llama3:latest`**. This capability allows full local execution and validation of the Conventional RAG pipeline without incurring external API costs, transmitting document data outside the local machine, or requiring Anthropic API keys.

The integration strictly respects all architectural constraints:
- **Zero LangChain or LangGraph:** The provider is implemented as a clean, plain-Python class adhering to the `LLMProvider` abstraction.
- **Provider Decoupling:** The RAG router dynamically selects between `AnthropicProvider` and `OllamaProvider` based on environment configuration (`LLM_PROVIDER`). When set to `ollama`, Anthropic credentials are not checked or initialized.
- **Zero Hallucination / Cost on Empty Evidence:** Retrieval-based refusal operates identically across both providers—if retrieval yields zero relevant chunks, an explicit refusal is returned immediately with zero LLM inference.
- **Deterministic Citation Validation:** Source tags (`[S1]`, `[S2]`) generated by Llama 3 are parsed and validated by the existing `CitationValidator`.

2. **Ollama `llama3:latest` Footprint:** The 8-billion parameter Q4_K_M quantized GGUF model occupies **4.34 GB** on disk and approximately **4.5–5.0 GB** resident memory during inference.
3. **RAM Contention Risk:** When host available RAM drops below 4.5 GB, loading `llama3:latest` into memory triggers Windows virtual memory paging. While Ollama handles pagefile swapping gracefully without crashing, CPU inference throughput drops noticeably during paging.

## 4. Plain-Python OllamaProvider Implementation

The `OllamaProvider` class is implemented in `backend/services/ollama_provider.py` as a concrete subclass of `LLMProvider`.

### 4.1 Request Protocol
The provider communicates with Ollama's native chat endpoint (`POST /api/chat`) using an asynchronous `httpx.AsyncClient`:

```python
payload = {
    "model": self.model,
    "messages": messages,
    "stream": False,
    "options": {
        "temperature": temperature,
        "num_predict": max_tokens,
        "num_ctx": self.num_ctx,
    },
}
```

### 4.2 Latency and Token Usage Tracking
Ollama returns execution metadata in its non-streaming response body:
- `prompt_eval_count`: Mapped to `TokenUsage.prompt_tokens`.
- `eval_count`: Mapped to `TokenUsage.completion_tokens`.
- `total_duration`: Converted from nanoseconds to milliseconds (`total_duration / 1e6`) for pipeline telemetry.

### 4.3 Exception Normalization
Underlying `httpx` and HTTP errors are mapped deterministically to the project's standard `LLMProviderError` hierarchy:

| Ollama / HTTP Condition | Normalized Exception | HTTP Status Code Mapping |
|---|---|---|
| `httpx.ConnectError` | `LLMServiceUnavailableError` | 503 Service Unavailable |
| `httpx.TimeoutException` | `LLMTimeoutError` | 504 Gateway Timeout |
| HTTP 404 (Model not found) | `LLMProviderError` | 502 Bad Gateway |
| Empty / Malformed JSON body | `LLMResponseMalformedError` | 502 Bad Gateway |
| Other HTTP 4xx / 5xx | `LLMProviderError` | 502 Bad Gateway |

## 5. Configuration & Conservative Token Sizing

In `backend/config.py`, configuration options were added to manage local inference conservatively:

```python
llm_provider: str = Field(default="ollama", description="LLM provider: 'anthropic' or 'ollama'")
ollama_base_url: str = Field(default="http://localhost:11434", description="Ollama API base URL")
ollama_model: str = Field(default="llama3:latest", description="Ollama model identifier")
ollama_timeout_seconds: float = Field(default=120.0, description="Ollama request timeout in seconds")
ollama_temperature: float = Field(default=0.1, description="Ollama temperature")
ollama_num_ctx: int = Field(default=2048, description="Ollama context window size")
ollama_max_tokens: int = Field(default=512, description="Ollama maximum completion tokens")
```

### Context Window & Limit Sizing Rationale:
1. **`ollama_num_ctx = 2048`:** Restricting the KV-cache allocation to 2,048 tokens limits RAM overhead compared to the default 8,192 window. Since Phase 8 retrieves top-$K=5$ chunks with conservative character budgets (~2,000–3,000 characters total context), 2,048 tokens is ample for context and prompts while protecting physical RAM.
2. **`ollama_max_tokens = 512`:** On an 8-core CPU without CUDA, token generation speed for Llama 3 is approximately 10–15 tokens per second. Capping completion tokens at 512 guarantees responses complete within 30–50 seconds, preventing long request stalls.
3. **`ollama_timeout_seconds = 120.0`:** Accommodates potential cold-start model load from disk into RAM when inference is first invoked.

## 6. Provider Selection & Decoupling

In `backend/routers/rag_answer.py`, the dependency provider factory was updated to dynamically inspect `settings.llm_provider`:

```python
def get_llm_provider(settings: Settings = Depends(get_settings)) -> LLMProvider:
    provider = settings.llm_provider.lower().strip()
    if provider == "ollama":
        return OllamaProvider(
            base_url=settings.ollama_base_url,
            model=settings.ollama_model,
            timeout_seconds=settings.ollama_timeout_seconds,
            temperature=settings.ollama_temperature,
            num_ctx=settings.ollama_num_ctx,
            max_tokens=settings.ollama_max_tokens,
        )
    elif provider == "anthropic":
        return AnthropicProvider(
            api_key=settings.anthropic_api_key,
            model=settings.anthropic_model,
            timeout_seconds=settings.anthropic_timeout_seconds,
            max_tokens=settings.anthropic_max_tokens,
            temperature=settings.anthropic_temperature,
        )
    else:
        raise ValueError(f"Unsupported LLM provider: '{settings.llm_provider}'")
```

When `llm_provider == "ollama"`, `AnthropicProvider` is never instantiated, and `settings.anthropic_api_key` is not evaluated.

## 7. Citation Validation & Empty Evidence Guarantees

Both providers share identical post-processing logic in `AnswerGenerator`:
1. **Empty Evidence Bypass:** If `rag_context.has_evidence is False`, `AnswerGenerator.generate_answer()` exits immediately without calling `provider.generate()`. Zero LLM tokens are used, and zero inference is performed.
2. **Citation Validation:** Output text is parsed by `CitationValidator`. Tags such as `[S1]` and `[S2]` are matched against `rag_context.sources`. If Llama 3 references `[S1]`, it is validated as a resolved citation. Uncited retrieved sources are tracked, and any hallucinated citations (e.g., `[S99]`) are tagged as invalid.

## 8. Hardware Guidelines & Concurrency Rules

To ensure reliable local execution on this AMD Ryzen 7 7730U machine:

1. **Strict Single Concurrency (No Parallel LLM Requests):** Local CPU inference consumes all 16 threads during prompt evaluation. Do not run concurrent LLM answer queries; requests must be serialized.
2. **Close Unneeded Host Applications:** Before running live inference, ensure browsers or heavyweight background tasks are minimized to keep available RAM above **4.5 GB**.
3. **Preserve RAM Guardrail:** Never bypass `EmbeddingService._check_ram_safety()`. If available RAM drops below 500 MB, the system safely refuses model loading to protect system stability.
